Epic 1 turned recorded reality into first-class, append-only data: a `field_event`
journal, a single transactional write path, projections onto task settled-state,
skip/correct from the UI, coherent rendering everywhere, and machine-checked
invariants — with dogfooding starting at 1.4 as planned.

## What went well

- **The single write path (`record_fact`, 1.2)** is the spine of the epic: event
  append + projection in one transaction, so every gesture (done/skip/reopen)
  goes through it. Invariants I1–I2 became **structural**, not conventional. A
  lint test forbids any `UPDATE task SET <settled col>` outside `facts.rs`.
- **The 3-layer adversarial review earned its keep on every story**, finding real
  defects invisible to happy-path tests: dual-backend atomicity/ordering (1.1,
  1.2), the agenda-cap regression that made a freshly-skipped old task
  uncorrectable (1.5), the missing "vanish-from-future" (1.6), and — on *test*
  code — a self-fulfilling oracle (1.7).
- **One shared visibility predicate (`Task::display_state`, 1.6)** eliminated the
  triple `completed_on`/`skipped_on`/`overdue` derivation scattered across views;
  calendar, agenda and detail can no longer tell different stories.
- **The paper-loop harness (0.7) grew as designed**: `step_e1` filled at 1.4
  (facts → PrintDoc oracle), and the reusable state-machine generator landed at
  1.7 for the fact-invariant properties (and E2's interleaving properties).

## What was hard / traps

- **Self-fulfilling oracle (1.7):** the first property tests checked the model
  against the same model that drove the writes. The review caught it; the fix was
  an **adversarial** test that submits invalid-for-state gestures straight through
  `record_fact` (the gestures the UI never offers), plus honest re-framing of the
  "kill-injection" test (SQLite is per-transaction durable → drop+reopen is
  prefix-replay, not torn-write recovery).
- **Sprint-status flip after merge (recurring, 1.5/1.6/1.7):** `main` is protected
  and the status file is tracked, so the `done` flip lived in the working tree and
  had to ride the next branch. Small but repeated friction.
- **Real crash mid-write never injected:** the crash is modelled as drop+reopen
  (per-transaction durability); a true `SIGKILL` torn-write remains deferred since
  0.7.

## Decisions (Guy)

- **3-layer review stays default-ON for Epic 2**, on the schema/domain/generation
  stories (2.1 migration 0008, 2.2 ITK, 2.6 generation). Lighter mode is allowed
  on UI-grid-only stories (2.3, 2.4, 2.5, 2.7).
- **AI-4 (real SIGKILL mid-write) stays deferred**, tracked in `deferred-work.md`
  with rationale: `synchronous=FULL` fsyncs each fact before `record_fact`
  returns, so drop+reopen faithfully models a crash *between* transactions;
  mid-transaction torn-write is SQLite's reliability domain, not ours.
