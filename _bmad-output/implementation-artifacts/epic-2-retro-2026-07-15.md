## What went well

- **The plan grid (2.3)** — the largest new UI surface since the convergence began:
  spreadsheet-faithful, keyboard-first, locale decimals, derived read-only date
  columns. Landed clean despite the 3-layer Slint plumbing tax.
- **The dedicated `planned_planting` table (2.6)** — the "pre-placement phase"
  pattern: an **additive table** instead of relaxing a NOT NULL FK on `Planting`
  (which would force a dangerous SQLite rebuild + ripple across every reader). It
  sets up Epic 3 placement precisely — 3.2 converts these rows into real plantings.
- **Non-destructive regeneration (2.6)** — upsert-by-succession-index + trim, ids
  preserved: the same "don't resurrect settled work" discipline as the 1.3
  skip-aware guard.
- **Adversarial reviews earned their keep even on "lighter" stories**: the
  `succession_dates` OOM (2.3, capped at `MAX_SUCCESSIONS`), the position collision
  after delete-then-add (2.5, `len()`→`max+1`), the harness not re-asserting the
  planning dataset after crash/reopen (2.6), and the `Decimal` overflow panic in the
  needs aggregation (2.7, `saturating`). None were visible to happy-path tests.
- **The needs list (2.7) closed the epic honestly** — printing deferred to Epic 4 as
  a *disabled* button with a self-explaining tooltip, not a dead-end action.
- **AI-E1-2 applied on all 7 stories** — sprint-status flipped in-branch before
  merge. The post-merge working-tree carry friction from Epic 1 is gone.

## What was hard / traps

- **UTF-8 `.ftl` + `perl` = mojibake (2.6):** editing a Fluent file with a `perl -0pi`
  one-liner double-encoded the whole file («ratée» → «ratÃ©e»). The `printdoc` test
  caught it before commit. **New rule: never `perl` on `.ftl` — use the Edit tool.**
- **Slint `row` reserved word (twice — plan.slint, itk_editor.slint):** "Cannot
  override property 'row'" → rename to `data`. Recurring Slint gotcha.
- **Slint conditional-element property access:** reading a property of an element
  inside an `if` from outside → refactor to in-out props + `<=>` two-way binding.
- **VarietyOption name collision (2.3):** a new type clashed with plantings_view's →
  reuse the existing `list_variety_options`.
- **The 3-layer Slint plumbing tax:** every new page property touches three files
  (page.slint, main.slint re-declare+forward, wiring get/set/on). Predicted in the
  Epic 1 prep; real but manageable.

## Cross-story pattern

- **Read-path defensive posture** emerged as the epic's technical theme: unbounded
  domain inputs (`series` as `u32`, SQLite decimals as free TEXT) must **saturate or
  cap** in read/aggregation paths, never panic. `succession_dates`' cap (2.3) and the
  `saturating_mul`/`saturating_add` in `needs_view`/`plan_view` (2.7) are the same
  lesson. **Codified** into `project-context.md` + the review checklist (AI-E2-3).
