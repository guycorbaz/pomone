\chapter{Paramètres}
\label{chap:parametres}

\section{Choix de la base de données}

Pomone supporte deux moteurs de stockage :

\begin{itemize}
  \item \textbf{SQLite} (par défaut) : un fichier local unique, idéal pour un poste isolé. C'est la configuration recommandée pour la majorité des utilisateur·rices.
  \item \textbf{MariaDB} : un serveur partagé, utile si plusieurs personnes saisissent depuis différents postes (en réseau local).
\end{itemize}

\subsection{Emplacement par défaut de la base SQLite}

Au premier lancement, Pomone crée automatiquement un fichier SQLite vide à l'emplacement standard de votre système :

\begin{itemize}
  \item \textbf{Linux} : \texttt{\~/.local/share/pomone/pomone.sqlite}
  \item \textbf{Windows} : \texttt{\%APPDATA\%\textbackslash pomone\textbackslash pomone.sqlite}
  \item \textbf{macOS} : \texttt{\~/Library/Application Support/pomone/pomone.sqlite}
\end{itemize}

Vous pouvez modifier ce chemin depuis le formulaire \emph{Édition de la configuration} ci-dessous : changez la valeur du champ \textbf{Chemin SQLite}, testez la connexion puis enregistrez. Pour déplacer une base existante vers un nouveau chemin, utilisez \textbf{Enregistrer et migrer} (voir section suivante).

\begin{notebox}
Pensez à sauvegarder régulièrement ce fichier \texttt{.sqlite} — c'est la totalité de vos données. Une simple copie sur disque externe ou cloud personnel suffit.
\end{notebox}

\subsection{Tester une connexion}

Le bouton \textbf{Tester la connexion} valide les paramètres sans rien modifier. Utile avant de basculer pour vérifier que MariaDB est accessible.

\subsection{Enregistrer}

Le bouton \textbf{Enregistrer} sauvegarde la configuration et redémarre le backend. Si vous basculez d'un backend à l'autre, vos données existantes \textbf{ne sont pas} déplacées.

\subsection{Enregistrer et migrer}

Le bouton \textbf{Enregistrer et migrer} sauvegarde la configuration et \emph{copie toutes vos données} depuis l'ancien backend vers le nouveau. Utile pour migrer un poste isolé (SQLite) vers un serveur partagé (MariaDB) ou inversement.

\begin{warnbox}
La migration peut prendre quelques secondes pour une base de taille modeste. Pour les bases volumineuses, prévoyez une fenêtre de maintenance.
\end{warnbox}

\section{Unités d'affichage}
\label{sec:parametres-unites}

La carte \textbf{Unités d'affichage} choisit les unités utilisées pour afficher \emph{et saisir} les surfaces et les rendements :

\begin{itemize}
  \item \textbf{Surfaces} : m² (par défaut, adapté au maraîchage) ou \textbf{ha} (grandes cultures) ;
  \item \textbf{Rendements} : \textbf{kg} (par défaut) ou \textbf{t} (tonnes).
\end{itemize}

Le changement est immédiat : les listes (plantations, lieux), la fiche de détail et les libellés des formulaires basculent dans l'unité choisie. Les champs de saisie suivent aussi : en mode hectares, saisir \texttt{8} dans le formulaire de plantation crée une plantation de 8~ha.

\begin{notebox}
Les données sont toujours \textbf{stockées} en m² et en kg, quelle que soit l'unité d'affichage — changer d'unité ne modifie jamais vos données et se fait sans risque, dans les deux sens. Voir le chapitre~\ref{chap:grandes-cultures} pour l'utilisation de Pomone en grandes cultures.
\end{notebox}

\section{Langue}

Pomone est disponible en \textbf{français} et en \textbf{anglais}. Le bouton de bascule se trouve dans le pied de la barre latérale. La langue choisie est persistée et restaurée au prochain démarrage.

\begin{notebox}
\textbf{Prévu.} D'autres préférences héritées de Qrop — sélecteur de thème (clair / sombre), affichage en semaines plutôt qu'en dates — sont envisagées pour une version ultérieure.
\end{notebox}
